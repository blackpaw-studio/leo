Leo · Web UI redesign

Three visual directions

Same content in each mockup: sidebar/nav, a slice of the task list, and a piece of a config form — the surfaces you use most. Fonts are system approximations; the real build ships proper embedded faces.

All three assume the structural changes we agreed on: sidebar navigation replacing the tab row, config-editing as the first-class surface, schema-driven forms.

A

Ops Terminal

The current UI's heritage, done properly. Committed dark, all-mono type, amber as the single interactive accent (green/red reserved purely for status). Dense, keyboard-feeling, reads like a well-configured tmux status line. Best if Leo should feel like part of the terminal.

B

Control Panel

A quiet settings-app idiom — the Tailscale-admin school. Humanist sans, generous grouped forms with inline help, toggles for booleans, warm lion-gold accent on warm-biased neutrals. Light and dark both first-class. Best for config-editing ergonomics; friendliest on a phone.

Instrument Panel

My lean: B (Control Panel), with A's status line grafted on top. You said config editing is the primary job and the phone matters sometimes — B's grouped forms, inline help, and toggles are built for exactly that, and it collapses to mobile most gracefully. A is the best pure monitoring look but its density works against form-heavy screens; C is the most striking but the all-caps grid gets loud across 24 tasks' worth of editing.
