# Cross-workspace dispatch read grants — implementation plan

Spec: `docs/specs/2026-11-23-dispatch-read-grants.md` (source of truth). Builds on #348 (`internal/consult/confinement.go`, `internal/web/caller_workspace.go`). Order: config → pure grant logic → harness argv → `Start` wiring → surfaces. Each step: failing test first, commit at the end.
Review bar: fix P0/P1, any way a granted run writes to the target or reads the claude secret denylist, any way an ungranted caller reaches a target, and false refusals of legit grants.

## Verified facts

- Claude Code ([sandboxing](https://code.claude.com/docs/en/sandboxing.md), [settings](https://code.claude.com/docs/en/settings.md), [permissions](https://code.claude.com/docs/en/permissions.md), [CLI](https://code.claude.com/docs/en/cli-reference.md)):
  - `sandbox.enabled`; `sandbox.failIfUnavailable: true` (exit instead of running unsandboxed); `sandbox.allowUnsandboxedCommands: false` (strict; ignores `dangerouslyDisableSandbox`; `false` from `--settings` wins); `sandbox.autoAllowBashIfSandboxed`; `sandbox.filesystem.denyWrite` / `denyRead` (absolute/`~` paths, globs).
  - Default write scope = cwd + `--add-dir` + per-user temp → target workspace must be named in `denyWrite`.
  - Sandbox covers Bash + children only. Read/Grep/Glob/Edit follow `permissions.deny`: `Read(//abs/**)` (gitignore syntax, `//` = absolute), `Edit(...)` covers all edit tools; Read/Edit deny also feed the Bash sandbox; deny holds in every mode incl. `bypassPermissions`.
  - `--settings` sits above user/project/local, below managed; lists merge (can't clear `sandbox.excludedCommands` from elsewhere). `--setting-sources user` drops project/local settings (their hooks, exclusions, allow rules).
  - MCP tools, hooks, mods run outside the sandbox — accepted risk.
- Leo: `MergeSettingsArgs` (`internal/harness/claude/settings.go:145`) runs only on interactive (`interactive_runtime.go:224`); headless `taskArgs` (`args.go:88`) emits at most `--settings {}`. Codex `sandboxWritableRootsArgs` (`codex/sandbox.go:27`) always emitted; codex `permission_mode` fixed per template (`codex/options.go:13`), `approve-for-me` excludes `--sandbox`. `AdditionalMCPServers` (`record.go:215`) is the precedent for per-run options reapplied on continuation (`continuation.go:84`) and reopen (`interactive_runtime.go:154`).

## Resolved decisions

1. Codex allowed: `--sandbox read-only`, secret denylist not enforced (spec, Evan 2026-11-23). Opencode refused.
2. `--setting-sources user` on claude target runs (now in spec).
3. User-scope `sandbox.excludedCommands` in the run account: documented accepted risk.
4. `/api/v1` observe projection: no `target_agent` this PR.
5. Recorded grant for exempt callers: `caller:none`, `api_client:<name>`.
6. Nested children under a granted tree always keep the sandbox.
7. All target refusals use `invalidf` (`*ValidationError` → 400, excluded from the interactive→headless fallback at `handlers_consult.go:114`).
